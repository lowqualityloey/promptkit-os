## Findings

### R1 [P1] Restore the original manifest bytes instead of checking out the index

**Location:** package/test/smoke.sh:34; setup:27–29.

When the source package.json version is0.0.0, the smoke test modifies that file using npm version. Cleanup then runs git checkout -- package.json. If a developer already has unstaged description, metadata or script edits in that manifest, cleanup discards them and restores the index version. This happens after both successful smoke runs and downstream failures. The base test did not modify or reset the source manifest.

npm's --no-git-tag-version option does not protect those edits with a clean-tree check; the npm11.5.1 version implementation checks cleanliness only when gitTagVersion is enabled. [npm version source](https://github.com/npm/cli/blob/v11.5.1/workspaces/libnpmversion/lib/version.js).

**Correction:** Pack a temporary package copy, or save and restore an exact snapshot of the original bytes. Install cleanup before the first mutation so failure during version synchronization also restores state. Verify that a manifest with pre-existing unstaged edits remains byte-identical after success and failure, without resetting the index.

### R2 [P2] Checkout an unambiguous peeled tag commit

**Location:** .github/workflows/release-npm.yml:64.

The new git checkout "tags/$TAG" can select a local branch named tags/v1.9.1 instead of the tag v1.9.1. Manual dispatch permits choosing that branch, and actions/checkout creates its local branch before this step. If the branch and tag point to different commits, the added step stays on the branch, then packages and publishes its wrapper under the requested tag's version. The remote tag-existence check does not establish which commit checkout selected.

Git documents that a valid refs/heads/<name> selects branch mode. The v4 checkout implementation defaults to the event ref, strips refs/heads/ to the local branch name, and performs checkout -B with the remote start point: [Git checkout documentation](https://git-scm.com/docs/git-checkout), [checkout input-helper](https://github.com/actions/checkout/blob/11d5960a326750d5838078e36cf38b85af677262/src/input-helper.ts#L79), [ref-helper](https://github.com/actions/checkout/blob/11d5960a326750d5838078e36cf38b85af677262/src/ref-helper.ts#L34), [checkout implementation](https://github.com/actions/checkout/blob/11d5960a326750d5838078e36cf38b85af677262/src/git-command-manager.ts#L223).

**Correction:** Resolve refs/tags/$TAG^{commit}, checkout that exact commit in detached mode, and assert HEAD equals the resolved tag commit before packaging. Cover annotated tags and a same-named tags/<tag> branch pointing elsewhere.

### R3 [P2] Preserve the hardened smoke harness across historical-tag checkout

**Location:** .github/workflows/release-npm.yml:64; later invocation:159.

Checking out the entire selected tag replaces package/test/smoke.sh before it is executed. A manual retry for v1.9.1 therefore runs the historical simulated-extraction harness, not this PR's new packed-binary harness. That historical script downloads and extracts the canonical archive, then calls init.sh directly; it never executes the packed courier. The workflow can still publish a historical wrapper without exercising the binary, leaving F21 incomplete for tag retries.

Verified immutable historical sources: [v1.9.1 harness](https://github.com/lowqualityloey/promptkit-os/blob/02bbfc6d69955f8150176ffe68475642cda1dacd/package/test/smoke.sh#L25), [v1.9.0 harness](https://github.com/lowqualityloey/promptkit-os/blob/a5ef4900192af2441a010fffb31fccaf965aaa98/package/test/smoke.sh#L25).

**Correction:** Preserve the hardened harness independently of the selected package source, or package the tag in a separate checkout and run the current harness against it. The harness's package source and canonical release revision must remain explicitly selected; simply copying it elsewhere will require adjusting its repository-path handling. Verify an older tag whose own harness lacks packed-binary coverage.
