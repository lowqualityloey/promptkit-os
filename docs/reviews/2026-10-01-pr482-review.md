## R1 — [P2] Added source beginning with plus bypasses probe detection

**Changed location:** [workflows/commit.md:101](https://github.com/lowqualityloey/promptkit-os/blob/89214b22e7d2e27f4a1710bc32576105d3cfddaf/workflows/commit.md#L101).

The `^\+[^+]` filter rejects every added line whose actual source starts with plus. For example, valid JavaScript `++counter; console.log("DEBUG: probe");` produces a diff line beginning `+++counter`. The first grep drops it, the quiet detector finds nothing, and the fallback prints `CLEAN`.

**Correction:** identify additions within diff hunks; distinguish metadata from content without excluding all double-plus prefixes. Add a leading-plus probe case. Both new test models copy the same filter, while their positive fixtures begin directly with `console.log`, so current passing tests miss this.

## R2 — [P2] Git-quoted credential filenames bypass the filename gate

**Changed location:** [workflows/commit.md:94](https://github.com/lowqualityloey/promptkit-os/blob/89214b22e7d2e27f4a1710bc32576105d3cfddaf/workflows/commit.md#L94).

For root `.env.local backup`, porcelain output is `?? ".env.local backup"`. The new expression requires start/space/slash immediately before `.env`; the quote prevents a match. A quoted `private key.pem` similarly fails the end-anchored extension check. These credential files can therefore appear absent from the gate.

Git documents whitespace quoting and recommends the NUL-delimited variant for machine parsing. [Official git-status documentation](https://git-scm.com/docs/git-status#_porcelain_format_version_1).

**Correction:** parse `--porcelain -z` records, including rename fields; inspect actual basenames and apply exact template exceptions. Cover spaces, tabs/newlines, nested files, renames, and each permitted template.

## R3 — [P2] Early quiet matches can be classified as CLEAN under pipefail

**Changed location:** [workflows/commit.md:101](https://github.com/lowqualityloey/promptkit-os/blob/89214b22e7d2e27f4a1710bc32576105d3cfddaf/workflows/commit.md#L101).

`grep -q` may exit after finding a probe while the preceding grep still writes. Under `pipefail`, a resulting status vector `[0,141,0]` makes the pipeline fail despite a successful match. The fallback inspects only Git's zero status and prints `CLEAN`. This is a source-derived timing-dependent failure path, not an observed local reproduction.

GNU documents upstream failures caused by early grep termination; Bash documents that pipefail returns the rightmost nonzero status. [GNU grep manual](https://www.gnu.org/s/grep/manual/grep.html), [Bash pipeline semantics](https://www.gnu.org/software/bash/manual/bash.html#Pipelines).

**Correction:** consume the complete stream and preserve relevant statuses before classifying the result. Exercise the actual recipe with a large diff and early match under the documented shell settings. An inspection failure must never be classified as clean.

## R4 — [P2] Mixed-ending updates alter the END/postamble separator

**Changed location:** [init.ps1:774–775](https://github.com/lowqualityloey/promptkit-os/blob/89214b22e7d2e27f4a1710bc32576105d3cfddaf/init.ps1#L774); original separator consumed at [738–746](https://github.com/lowqualityloey/promptkit-os/blob/89214b22e7d2e27f4a1710bc32576105d3cfddaf/init.ps1#L738).

The offset walk consumes the END marker's original terminator. Replacement recreates it using `$nl`, selected from any CRLF anywhere in the file. A CRLF preamble with an LF END/footer separator consequently changes that separator to CRLF. The old boundary ended at the END marker itself, leaving its terminator untouched.

**Correction:** leave the original separator in the suffix or capture/reuse it exactly. Add a genuinely mixed-EOL PowerShell fixture and compare exact prefix/suffix bytes on the first replacement, including trailing-newline variants. Current tests use separate uniform LF/CRLF inputs and presence/start/end checks, so they do not establish the PR's mixed-ending preservation claim.

## R5 — [P2] Discovery and validation disagree on marker indentation

**Changed location:** [init.ps1:696–697](https://github.com/lowqualityloey/promptkit-os/blob/89214b22e7d2e27f4a1710bc32576105d3cfddaf/init.ps1#L696).

Discovery permits ASCII spaces/tabs only, while validation retains `.Trim()`, which accepts Unicode whitespace. A formerly accepted block with non-breaking-space indentation on both marker lines now appears absent. The append branch adds a second managed block and reports success; the next run fails duplicate-marker validation. An indented orphan can likewise evade rejection. [.NET Trim semantics](https://learn.microsoft.com/en-us/dotnet/api/system.string.trim).

**Correction:** use the same standalone-marker predicate for presence detection, counting, and boundary selection. Cover Unicode indentation and orphan markers, either preserving supported behavior or explicitly rejecting unsupported markers before any append.
