# Documentation Truthfulness Audit — 2026-10-02

- **Review ID**: `REVIEW-2026-10-02-doc-truthfulness-audit`
- **Status**: `complete`
- **Reviewed revision**: `3966f1607635cb00964082b4da773616fc97121f`

Audited `docs/WORKFLOW-MAP.md`, `FAQ.md`, `docs/DESIGN-MD-FAQ.md`, and `docs/INTERESTING-FACTS.md` at `3966f1607635cb00964082b4da773616fc97121f`. This is a claim-to-source audit, not a live-host compliance test. `bash scripts/validate-references.sh .` passed, so the findings concern accuracy and scope rather than broken Markdown links.

## Findings, ordered by impact

1. **High — security guarantees exceed the actual controls.** `docs/INTERESTING-FACTS.md:282` says RLS makes querying another tenant's data “impossible.” PostgreSQL documents bypass by superusers, `BYPASSRLS` roles, and normally table owners, plus policy-design caveats ([PostgreSQL row security](https://www.postgresql.org/docs/current/ddl-rowsecurity.html)). Line 298 says `SameSite=Lax` “prevents CSRF”; `workflows/auth.md:41-43` correctly says it is incomplete and requires independent CSRF checks, consistent with [MDN's CSRF guidance](https://developer.mozilla.org/en-US/docs/Web/Security/Attacks/CSRF). `FAQ.md:536-543` likewise promises “Zero Accidental Contamination” from database-isolation instructions, although the product is an instruction layer, not a sandbox. Replace absolutes with defense-in-depth language and link to the existing workflow requirements.
2. **High — benefit and cost outcomes are stated without outcome data.** `FAQ.md:47-62` promises faster work after one week, a 36-minute payback, and zero context loss without a measured cohort or derivation; `protocols/context-sync.md:123` explicitly says unrecorded in-flight reasoning is not recovered. `FAQ.md:251-308` does label token scenarios as modeled, but then calls 60–70% an “Average” without weights (the five displayed percentages have an unweighted mean of 81%), gives a “typical developer” dollar saving without a pricing/input model, and predicts 50–70% from a future self-test. `FAQ.md:332-335` turns modeled 85% into a user outcome. Keep the mechanically measured static/per-task payload figures from `docs/BENCHMARKS.md:31-48,95-101`, and label all time, session-token, and dollar examples as illustrative assumptions until observed.
3. **Medium — universal host compatibility is untested.** `FAQ.md:78-93` and `docs/INTERESTING-FACTS.md:541-552` say the kit works across all/major assistants. `docs/HOST-CONFORMANCE.md:23,48-54,78-80` explicitly registers every host as untested for live behavioral fidelity; its passing cases are staged scorer fixtures. Distinguish installer/configuration support from verified agent behavior.
4. **Medium — the workflow map's lifecycle graphic teaches incorrect ordering.** `docs/WORKFLOW-MAP.md:550-608` starts greenfield at `pk:plan`, places `pk:spike` after implementation, and presents `pk:ship` and `pk:checkpoint` as downstream stages of every task. `workflows/onboard.md:53-57` and `docs/WORKFLOW-MAP.md:184-186,225-227` put empty-repo discovery at `pk:onboard`; `pk:spike` resolves design uncertainty; `pk:ship` is release-specific; checkpoints occur at session/role boundaries. The graph at `docs/WORKFLOW-MAP.md:273-329` is an illustrative cluster map, but `Tasks → Commit` similarly hides build and verification. Label these as non-executable illustrations or redraw with conditional branches. The “Typical Duration” figures at lines 454–478 are not tied to measurements; mark them estimates or omit them. Line 54's present-tense claim that v1.1.0 is not approved is stale beside the v1.10.0 release recorded in `CHANGELOG.md:22`.
5. **Medium — the DESIGN FAQ overstates scope and safety.** `docs/DESIGN-MD-FAQ.md:10,27-35,279-280` correctly says the *installer* detects but does not write `DESIGN.md`. Lines 11 and 348 expand this into “all workflows” and “completely safe,” although the FAQ's own workflow table at lines 62–71 names only relevant UI workflows and `workflows/onboard.md:209-215` may create a missing design file or change an existing one after explicit human confirmation. State the installer guarantee separately from agent-workflow behavior and avoid implying mechanical enforcement of every custom format.
6. **Medium — examples are recast as universal requirements.** `docs/INTERESTING-FACTS.md:54-56` titles UUIDv7 a default using only a sample project's invariant; `workflows/data.md:25` actually prefers UUIDv7 *or* CUID2 for high-write tables. Line 320 mandates cursor pagination for all lists while `workflows/api.md:139,161` permits cursor or offset and reserves the cursor recommendation for high-velocity collections. Line 365 mandates Zod at all boundaries, contrary to `templates/tech-spec-template.md:217,241`, which calls for the project's native runtime validation. There is also a real source-level inconsistency: `workflows/api.md:135,169` itself requires Zod despite the stack-neutral template. Align that workflow and use conditional wording in the facts page.
7. **Medium — “zero documentation” contradicts the recommended minimum.** `FAQ.md:205-220` recommends `pk:checkpoint` while saying this creates no documentation; the same section says checkpoint updates `docs/STATE.md`. Say users need not write specs/ADRs manually, while checkpoint persists a state file. `FAQ.md:499` says “zero static token bloat” even though `docs/BENCHMARKS.md:35-36` measures 1,274/2,318 estimated tokens of static directive. Say “smaller static footprint,” not zero. `FAQ.md:408` says PromptKit is Markdown, not code, overlooking its installers, validators, and courier.
8. **Low — old metadata and unsupported absolutes remain.** `FAQ.md:642-643` is stamped 2026-09-18/v1.7.0 while `CHANGELOG.md:22` records v1.10.0. `docs/INTERESTING-FACTS.md:250` says referencing an artifact costs zero additional tokens; lines 497 and 537 promise 3× faster parallel work and one-step removal without evidence or full removal steps. Replace with qualified examples. `docs/WORKFLOW-MAP.md:5-11` labels a five-node introductory sequence “Lite” although the Lite directive's six loaded workflows do not include `pk:plan` or `pk:tasks` (`docs/BENCHMARKS.md:35`); rename it an introductory map or explain that those links require Balanced/on-demand access.

## Claims that held up

- The repository has 25 workflow files and a cross-linked Level 0–3 authority model. `docs/WORKFLOW-MAP.md:19-52` matches the route, plan, tasks, checkpoint, review, and ship ownership boundaries at a high level.
- Installer code only detects an existing root `DESIGN.md` (`init.sh:409-421`, `init.ps1:418-431`); it has no design-file write path.
- All 16 stack playbooks measured below their stated 1,500-token `bytes/4` ceiling. The token measure is an estimate of file payload, not observed model usage.
- The current brownfield onboarding text preserves confirmed intake values and human overrides (`workflows/onboard.md:197-211`), addressing the earlier PR #497 finding at the merged head.

No source documents were edited in this audit. Priority order for correction: security absolutes, empirical outcomes, host fidelity, lifecycle diagrams, then the remaining FAQ/facts wording.
