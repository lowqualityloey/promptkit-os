## Finding

### R1 [P2] Use recorded all-history bounds when there is no approved predecessor

**Location:** workflows/ship.md:194.

The updated sentence correctly uses the latest approved predecessor for normal releases, but adds an approved immutable v1.0.0 fallback "for initial releases." That conflicts with the canonical procedure it is intended to match. docs/internal/release-evaluation.md:19 says an evaluation with no prior Approved Release Record is First Release and records the all-history starting point. Lines28 and33 likewise require that recorded first-release history. templates/release-checklist.md:64–65 specifies N/A for both the predecessor record and exclusive approved baseline in this case.

Following the new exception can demand an approved baseline that does not exist, or truncate the initial reviewed history to commits after v1.0.0. It retains an incorrect first-release boundary while fixing the ordinary-release boundary.

**Correction:** Use the predecessor's Approved Release Candidate Commit as the exclusive baseline when one exists. For First Release, use the recorded all-history start without a hardcoded version exception. Continue preserving historical approved records and the existing human-only action boundary.

Source references: [changed sentence](https://github.com/lowqualityloey/promptkit-os/blob/5b97e51aef413a627b866521075966bcdd47be31/workflows/ship.md#L194), [canonical First Release procedure](https://github.com/lowqualityloey/promptkit-os/blob/5b97e51aef413a627b866521075966bcdd47be31/docs/internal/release-evaluation.md#L19), [candidate-inclusive range](https://github.com/lowqualityloey/promptkit-os/blob/5b97e51aef413a627b866521075966bcdd47be31/docs/internal/release-evaluation.md#L28), [checklist fields](https://github.com/lowqualityloey/promptkit-os/blob/5b97e51aef413a627b866521075966bcdd47be31/templates/release-checklist.md#L64).
