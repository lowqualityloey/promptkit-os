## Findings

### R1 [P2] Bind diagnostic evidence to the staged content snapshot

**Location:** workflows/review.md:98; related commands:93–96, contract:59.

The new staged-mode scope explicitly excludes unstaged edits. However, typecheck/lint commands still inspect the live working tree, and the changed diagnostic filter accepts evidence solely by staged filename. If src/example.ts has a valid staged number assignment and an unstaged string assignment, the live typecheck error is accepted as a blocking staged-review finding even though the index version is valid. An unstaged correction can likewise hide a staged error.

This is an incomplete fix of issue #479's selected-mode isolation, rather than a claim that this PR introduced the original diagnostic commands. The mode-appropriate diff passed to the verifier is corrected, but filename filtering does not establish which contents produced the diagnostics.

**Correction:** Inspect an independent snapshot containing the selected index/committed versions without altering the user's index. If matching-version diagnostics cannot be obtained, mark them unavailable and continue the source review; do not attribute live-working-tree evidence to the index. Verify a file with differing staged and unstaged contents in both directions, including an out-of-scope file influencing its diagnostic.

### R2 [P2] Capture helper process status and success output in PowerShell failure tests

**Location:** scripts/tests/run-worktree-isolation-tests.ps1:46–58; repeated at89–101.

The collision and conflicting-merge cases directly invoke the helper, capture only stream 2 into the ordinary output stream, then inspect LASTEXITCODE. The helper's success messages use Write-Host, which writes to information stream 6; these messages are absent from the strings searched for false success. Direct script invocation also exposes the failing Git command's LASTEXITCODE even when the helper continues to its success message. Consequently the old helper can satisfy the nonzero check and evade both false-success assertions. A terminating-error catch additionally replaces any preceding captured output with the exception string.

**Correction:** Invoke a child pwsh -File process, capture its complete console output and its process exit status, and assert nonzero status plus absence of success output. Retain output even when execution fails. Demonstrate that the checks reject a helper with the failure guards removed, rather than only passing the corrected helper.

Official references: [PowerShell output streams](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_redirection?view=powershell-7.5), [LASTEXITCODE semantics](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_automatic_variables?view=powershell-7.6).
