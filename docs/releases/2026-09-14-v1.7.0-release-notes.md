## Profiles, Switching, and Ceremony Truth

**2+1 Profiles, now first-class.** Install-time profile selection (`--lite`, `--balanced`, `--turbo --experimental`) with an interactive TTY picker, plus the new **`pk:profile` runtime switcher** — change Lite/Balanced/Turbo in-session; switching delegates to the idempotent installer path and verifies result + token footprint. Lite = 6 utility workflows / 983 tok; Balanced = 23 workflows / 2,404 tok (both budget-gated in CI).

**Installer hardening.** Non-interactive detection fixed (piped stdin, redirected stdout, VS Code terminals, documented `PROMPTKIT_NO_INTERACTIVE=1`), PROMPTKIT.md `## 0.` body now stays in sync on re-runs, and `CONVENTIONS.md` (Aider) is injected when present — matching the host matrix promise. New e2e profile-matrix harness covers all three profiles on Linux + Windows.

**Ceremony guards.** Level classification gains a deterministic **tie-break (highest wins)**, **announced-and-logged L2 downgrades** (silent downgrade = violation), and the **milestone boundary is finally defined** — scoped to your task's own changes with an explicit post-init exception for pre-existing untracked files.

**Honest numbers everywhere.** Turbo's protocol overhead is now measured (**1.0x-2.0x**, not the previously advertised "3-5x") and CI-gated; the unsourced "18.5k monolithic" baseline is replaced by derived baselines (core-subset ~19.8k / full-set ~75.5k); workflow counts, FAQ totals, and per-task payloads reconciled to live measurements with drift tripwires so they cannot silently rot again.

**Engineering hardening (what your assistant inherits).** CI now **self-validates every task record** (execution-control `--root .` on both OSes — a class of silent governance decay closed), directives carry **session-endurance**, **STATE-until-read**, and **telemetry-provenance** rules (no green status cards without a this-turn executed check), trigger names are uniqueness-gated, and `sync.md` — the drift-recovery path — is factual again.

## BREAKING CHANGE (minor release, documented)

`pk:profile` was an alias of `pk:perf` since v1.0.0; it now exclusively names the profile switcher. If you typed `pk:profile` for profiling, use **`pk:perf`** or **`pk:latency`** (intent-based auto-routing is unaffected). Nothing else changes; all existing artifacts remain valid — upgrade = `git submodule update --remote .promptkit && ./.promptkit/init.sh`.
