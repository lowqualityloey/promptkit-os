## The Credential Is Gone From The Publish Step

**No more long-lived write token.** The npm courier publish step no longer authenticates with the `NPM_TOKEN` repository secret. It now uses npm trusted publishing: the job presents a short-lived OIDC credential minted from its `id-token: write` permission, and npm exchanges it for a one-time publish grant. There is no standing write credential left in the repository to leak, rotate, or audit.

**This was a deadline, not a nicety.** `promptkit-os@1.9.0` shipped on a granular access token created with `bypass_2fa`. npm removes direct publishing through bypass-2FA tokens in **January 2027**. Because npm versions are immutable, discovering that at release time costs a version number and a new tag — so the migration lands now, while the package is small and the fix is one file.

## The Part That Actually Bites

**The gate is the npm CLI, not Node.** Trusted publishing requires **npm >= 11.5.1** and **Node >= 22.14.0**. The workflow ran on `node-version: "20"`, which bundles npm 10 — and npm 10 does not merely publish without provenance, it *never attempts the OIDC exchange at all*. With `NODE_AUTH_TOKEN` removed it simply cannot authenticate. Removing the token and enabling OIDC support are two separate layers, and the token removal alone would have shipped a publish step that failed at the last second.

Bumping `node-version` alone is not a reliable fix: Node 22 can bundle npm 10, and early Node 24 shipped npm 11.4.x — still below the floor. So the publish job now pins the CLI explicitly with `npm install -g npm@^11.5.1` after setup. `node-version` stays at 20, because it was never the gate.

**Leave the Environment field empty.** The npmjs.com trusted-publisher entry has an optional *Environment* field. This job declares no `environment:` key, so a non-empty value there makes the OIDC exchange fail with a publisher mismatch that reads like a permissions bug. The workflow documents this at the publish step.

## Nothing Else Changed

No workflow, protocol, template, installer, or directive was touched. `init.sh` / `init.ps1` remain the single source of truth, `templates/agent-directive-template.md` is byte-unchanged, and the AC-1 smoke test still runs **before** publish — a version never reaches the registry unverified. `permissions` (`contents: read` + `id-token: write`), the minimal-tarball assertion, and `--provenance` are unchanged. Consumers see nothing: no upgrade step, no behavior change.

## What Still Needs You

The pipeline no longer *uses* the token; it does not yet *retire* it. In order: configure the trusted publisher on npmjs.com (Environment empty) → cut a tag → confirm a token-free publish → verify `npm view promptkit-os dist.attestations` → **then** delete the `NPM_TOKEN` secret. Note that the first OIDC validation consumes a fresh version, because npm versions are immutable — it cannot be rehearsed against `1.9.0`. Token revocation on npmjs.com is independent of the secret deletion and should not wait for it.
