### Added
- **Phase 3b seed-neutralization procedure**: `benchmarks/seed/neutralize.sh` produces the neutral seed both arms of a Phase 3b run start from, so the protocol's Appendix B "neutralization procedure SHA" names a reproducible step instead of an operator's memory. It clones the source (tracked content only, so ignored build output and untracked scratch files cannot leak in) and removes exactly the instruction-surface set `benchmarks/run-ab-benchmark.sh` refuses — `AGENTS.md`, `CLAUDE.md`, `PROMPTKIT.md`, `GEMINI.md`, `.cursorrules`, `.windsurfrules`, `.clinerules`, `copilot-instructions.md`, `.cursor/rules/`, `.claude/`, `.promptkit/`, `.github/instructions/` — then fails closed if a `heyloey` reference survives, since that cannot be scrubbed without risking a silent change to what a task asks for. A dirty source tree, a non-git source, and a dest holding different content are all refused (exit 2); the neutralization commit uses a fixed identity and timestamp, so identical source content yields an identical seed SHA on any host, and re-running against an already-neutralized dest reports `NEUTRALIZE|ALREADY` instead of overwriting. It emits one `NEUTRALIZE|OK|source=…|seed=…|removed=…|script_sha256=…` line. Exercised against synthetic fixture repositories: surface removal, cross-dest SHA reproducibility, idempotent re-run, and each refusal path. It is registered in the CI Bash syntax list beside `benchmarks/run-ab-benchmark.sh`. It does not run the seed's test suite or the task `Verify` commands — the protocol requires both, and only the operator knows the seed's install and test commands. Behavior-surface paths: `benchmarks/seed/neutralize.sh`.

- **CPAC real telemetry ingestion (§5 record scoring + Command Code extraction)**: the CPAC utility is no longer simulated-only. New `scripts/extract-commandcode-telemetry.sh`/`.ps1` convert a Command Code session transcript (`~/.commandcode/projects/<slug>/<session>.jsonl`, JSONL schema v3) into the standardized telemetry record defined in `docs/BENCHMARK-METHODOLOGY.md` §5 — successful-turn token sums split from rework turns by a documented turn-walk rule, tool-call totals with a best-effort search/edit/verify classification, human interventions (user prompts after the first), wall clock from the first/last event timestamps, the last assistant model, and cache-read tokens reported but excluded from `C_inference` (the v1 cache convention, since §2 prices a single input tier); `accepted` defaults to `false` with a loud stderr note because acceptance is a human judgment. `scripts/measure-cpac.sh`/`.ps1` now score such a record from a path argument: required keys validated fail-closed (exit `2` with `CPAC|ERROR|MISSING_KEY|<key>` / `BAD_VALUE` / `UNREADABLE` diagnostics) and a measured scorecard plus a `CPAC|MEASURED|...` machine line printed, with new pricing override flags (`--price-in/--price-out/--rework-tool-cost/--human-rate`; PS `-PriceIn/-PriceOut/-ReworkToolCost/-HumanRate`) for cross-model repricing. Both twins reach byte-identical records and machine lines from identical inputs (verified on a real transcript); the Bash extractor is a dependency-free awk state machine (no jq/python/node), and transcript-derived values never re-enter the shell parser. The simulated scorecard is preserved, labeled, behind `--demo`/`-Demo`. ## [2.0.1] - 2026-10-25

### Added
