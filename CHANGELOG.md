## [Unreleased]

### Added
- **Real `pk` Entry Point + Installer-Verified Host Coverage (#546)**: `pk route "<text>"` (`scripts/pk` / `.ps1`) is a thin router shim — it delegates verbatim to the ceremony classifier (`scripts/pk-route.{sh,ps1}`) and propagates its exit code, or exits `2` for any other subcommand while naming `workflows/<cmd>.md` as the file-level contract (`pk commti` fails loudly instead of silently succeeding). It classifies and prints only: no daemon, no network beyond `pk-route`'s existing optional probe, no file writes, no workflow execution — a hand-written shim, none of the binary/npm-dependency/daemon that `PROMPTKIT.md` §7 bans. Installer coverage is now verified at file level: a `--host=cursor` install writes the managed block into `.cursorrules`, and a multi-host install carries `<!-- PROMPTKIT_START -->` in every host file; both are regression-locked (`run-init-safety-tests.{sh,ps1}`) alongside a new entry-point harness (`run-pk-entry-points-tests.{sh,ps1}`) that pins `pk route` classification, the unknown-subcommand exit `2`, and Bash/PowerShell parity. `pk:route` resolves in shell and in every installed host file; the remaining triggers stay file-level prompt contracts. The adoption guide now names the committed universal `AGENTS.md` as the tracked default and per-host files as optional local overrides.
- **Read-Only Installed-Governance Doctor (`pk:doctor`)**: adds the `pk:doctor` workflow (`workflows/doctor.md`) and its read-only twin engines (`scripts/check-doctor.sh` / `.ps1`): one command audits hosts × engine version × install-mode × ignore-state × docs-drift and emits one tab-separated row per check (`OK` | `STALE` | `MISSING` | `IGNORED` | `DIVERGED` | `SKIP` | `INCOMPLETE`). It never edits, stages, commits, or upgrades; `IGNORED` reports a deliberate configuration without failing health, unavailable checks degrade to `SKIP(<reason>)`, and `INCOMPLETE` is fail-closed on exit `1` (exit `2` only when no check could run). Wired into CI alongside its regression harness (`scripts/tests/run-doctor-tests.sh` / `.ps1`) and registered across the directive, router, setup reference, architecture table, and workflow map; the locked workflow count moves to 26. (#547)
- **Read-Only Synthetic-Base Preflight**: a base-deriving operation can no longer silently compare against a synthetic workspace commit. `scripts/check-synthetic-base.sh` / `.ps1` refuses (exit `1`) only on **positive evidence** — the inspected commit is the **tip of** a tool-namespace ref (`refs/gitbutler/*`, `refs/orca/*`, `refs/codex/*`, `refs/cline/*`) and is carried by no branch — and prints recovery steps citing a new `docs/MAXIMS.md` invariant. An earlier commit that merely sits behind such a ref tip is ordinary and is **not** refused, because ownership must be evidence about the inspected commit itself. Absence of a carrying branch, a missing upstream, and a detached checkout (which satisfies both) are **corroborating only** and resolve to `UNKNOWN` and proceed, so a healthy repository is never blocked and `unpushed` is never a fault. Owned namespaces live in `scripts/synthetic-base-signals.txt` (`ref-namespace|<prefix>`, extendable via `PROMPTKIT_SYNTHETIC_REFS_EXTRA` or `--signals-file`), and a malformed or unreadable row fails closed (`2`). Wired into `scripts/check-changelog-entry.sh` / `.ps1` (`CHANGELOG_GATE|SYNTHETIC-BASE`; **both** range endpoints are inspected, and a preflight that cannot measure fails closed as `CHANGELOG_GATE|INCOMPLETE`) and `scripts/check-milestone-halt-evidence.sh` / `.ps1` (`repository|INVALID|synthetic-base` / `…-preflight`), and into `pk:sync`, `pk:review`, and `pk:pr`; the guard never gates committing or staging. New regression harnesses (`scripts/tests/run-synthetic-base-tests.sh` / `.ps1`, plus a synthetic case in the milestone-halt fixtures) cover all six acceptance scenarios. (#552)
- **Tool-Owned Branch Namespaces Count as Synthetic Bases**: the synthetic-base preflight previously recognized only an owned ref (`ref-namespace|`), which never fires for GitButler's real layout — its workspace commit is carried by the ordinary local branch `refs/heads/gitbutler/workspace` while `refs/gitbutler/` holds no refs, so the guard returned `OK` for the one tool it names first. The signals grammar now also accepts `branch-namespace|<prefix>`: the **tip of** a tool-owned workspace branch (shipping `gitbutler/workspace`) with no ordinary branch carrying it is positively tool-owned and is refused, while ancestry alone does not qualify and any ordinary carrying branch keeps the commit silent. The prefix is the workspace identity, not the whole `gitbutler/` namespace: GitButler's `refs/heads/gitbutler/target` is ordinary real history and must not match. Two hardenings from the #575 review land with it: both gates now fail closed when the detector file is absent instead of silently skipping the preflight (`CHANGELOG_GATE|INCOMPLETE` / `milestone-halt|repository|INVALID|synthetic-base-preflight-missing`), and the detector's namespace loops carry an explicit length guard so a comments-only custom signals file cannot abort under bash 3.2 `set -u`. The `pk:sync` note now says the **tip of** a tool-namespace ref (the implemented rule), and the regression harness covers the tool-branch-only, tool-branch-plus-ordinary, empty-namespace, and missing-preflight cases on both twins. (#576)
- **Tracked Narrative-Surface Scan in the Staged Gate**: `scripts/scan-staged-secrets.sh` and its `.ps1` twin now flag tracked narrative surface on the staged index (added lines only) alongside credential detection — absolute local paths (`/home/…`, `/Users/…`, `/mnt/c/Users/…`, `C:\Users\…`), internal planning markers, and project-supplied machine names — printing the `file:line` and a remediation and exiting the new `3` tier, while secret findings keep `1` and scan failures keep `2`. This closes the `.gitignore` asymmetry where a tracked `memory.md` or `handoff.md` publishes local paths, machine names, or an unreleased roadmap because only *untracked* files are ignored. Detector patterns and the allowlist are externalized as `scripts/narrative-surface-rules.txt` (`RULE|regex|severity`) and `scripts/narrative-surface-paths.txt` (`glob|kind`), seeded with this repository's two evidence-backed review records and extended per project through `PROMPTKIT_NARRATIVE_RULES_EXTRA` / `PROMPTKIT_NARRATIVE_PATHS_EXTRA`; a missing, unreadable, or malformed row fails the scan closed (`2`) so a typo cannot silently narrow coverage. Both twins gained the tier and matching regression cases in `scripts/tests/run-staged-secret-scan-tests.sh` / `.ps1`. (#551)
- **Install-Door Structural Assert**: both installers now verify the engine tree at the end of a successful install, before printing the success banner, by classifying which documented door produced it (`courier`, `direct-clone`, `submodule`, `standalone`) and asserting only what is structurally true for that door via `scripts/check-setup-assert.sh` / `.ps1` (manifest `scripts/setup-assert-files.txt`). An incomplete tree fails loudly as `partial-copy`, naming each missing required file and the remedy, and an unmeasurable git result is reported `INCOMPLETE` rather than read as OK, so a broken or partial install can no longer print success. The assert runs after the commit point, so a failure never triggers the transactional rollback, and `PROMPTKIT_NO_PREFLIGHT=1` downgrades it to an advisory `SKIP`. A gitlink with no matching `.gitmodules` entry, a `.gitmodules` entry with no staged gitlink, and a kit path tracked as regular content are each rejected rather than misclassified as a healthy clone. Covers all five documented install doors in both twins. (#549)
- **Read-Only Ignore Preflight for Checkpoint Targets**: `workflows/checkpoint.md` Phase 4 now runs the read-only preflight `scripts/check-checkpoint-ignore.sh` / `.ps1` (data file `scripts/checkpoint-targets.txt`) before writing, which runs `git check-ignore -v` on each checkpoint target and reports any target hidden by an ignore rule as `POLICY_LIMITATION` citing the matching rule verbatim. Unmeasurable git state fails closed as `INCOMPLETE` (exit 2) rather than reading as OK, and the preflight never stages, force-adds, commits, or un-ignores — the ignore rule is the author's publication policy and is surfaced, not overridden. New protocol `protocols/checkpoint-ignore-policy.md` documents the contract. (#548)
- **Progressive Checkpoint Compliance (L1 Quick Checkpoints)**: adds the `quick` checkpoint tier for Level 1 (Standard) work in `scripts/validate-execution-control.sh` and its `.ps1` twin, allowing fast-path progress recording without mandating a canonical Task Record (`docs/tasks/<task-id>.md`). Enforces ten canonical required labels (`Record Type`, `Checkpoint ID`, `Created`, `Execution State`, `Objective`, `Remaining Work`, `Blockers` with concrete value or `None identified`, `Next Action`, `Resume Condition`, `Recorded By`). `Task ID` is optional; absent Task ID is silent while supplied unresolved Task IDs emit `TRACEABILITY_MISSING`. Checkpoints derive their tier from established task ceremony classification, preventing weaker-gate self-selection or downgrades. Other full-contract labels degrade explicitly as `POLICY_LIMITATION` with machine-checkable tier and unresolved counts reported on both success and failure. Level 0 (Direct) writes to `docs/` are strictly rejected with `POLICY_LIMITATION` per `workflows/route.md`, while Level 2 (Controlled) and Level 3 (Release-Critical) retain the full 20-label gate. Added matrix fixtures (`quick-pass`, `quick-unlinked`, `quick-rejected`, `quick-placeholder`, `l0-no-write`) and updated adoption guidance. (#553)
- **Content-Anchored Citations in Public Specifications**: eight specifications for #546-#553 moved from gitignored scratch into `docs/specs/`, where `.gitignore` and `CONTRIBUTING.md` already placed them, and every evidence citation in them changed from `path/to/file.ext:142` to `path/to/file.ext` (anchor: `verbatim content`). A line-number citation rots silently: an unrelated edit shifts it and it keeps reading as valid, with nothing reporting the drift. These specs had already gone stale twice, once from a rebase and once from #556. All 310 anchors were checked against their targets during the conversion and resolve today. `CONTRIBUTING.md` item 7 records the grammar and its two rules, and states plainly that verification is by review rather than by CI — a known gap, since a gate was considered and judged premature while the issues these specs describe remain unmerged.   The one gate change the specs require is a scoping fix. `validate-references.sh` asserts that every `pk:` trigger named in a scanned document has a matching workflow file, and the behavioral contract requires a zero-warning run. A specification's subject is frequently the trigger it proposes to add, so #547 legitimately names a trigger whose workflow file does not exist yet — committing an accurate spec failed the build for being accurate, leaving only two bad escapes: mangle the trigger token out of the prose, or ship the workflow early. `docs/specs/` is now exempt from the trigger scan only; link checking and every other check still apply, the trigger-to-workflow correspondence is still enforced where triggers actually ship (the directive templates and `protocols/setup.md`), and the exemption policy is the one the link checker already applies to `docs/tasks/` and `docs/releases/`. Mirrored in the `.ps1` twin.

Each now carries the re-measure and repropagate obligation. One stale figure was corrected (2,350 → 2,312).

  Review of the eight specs then found three defects in the specifications themselves, corrected here rather than deferred to implementation. (1) *#550 required a count its own Given could not produce.* Scenario 2 supplied only branch, revision, and next action, then demanded exactly 15 unresolved labels with `Task ID` excluded -- but `Task ID` is one of the 17 value-bearing labels and is separately required to resolve in `TASK_FILE_BY_ID`, so a payload without it produces 16 `CHECKPOINT_INCOMPLETE` **plus** a `TRACEABILITY_MISSING`. Measured both ways against the real validator: with a resolvable Task ID `FAILED|ERRORS=15`, without it `FAILED|ERRORS=17`. The `ERRORS=15` baseline was genuine but had been measured from the 5-field payload, not the 3-field one the scenario described; linked and unlinked are now separate scenarios with separate fixtures. (2) *#552's proposed detection evidence also matched a legitimate detached HEAD.* `git branch --contains HEAD` empty with no upstream is the ordinary state of a detached checkout, so treating those two signals as sufficient would refuse a healthy repository and contradict the spec's own evidence-based-refusal invariant. Refusal now requires positive evidence of a tool-owned commit; the two signals are corroborating only, and a detached-HEAD fixture that must resolve `UNKNOWN` is mandatory rather than optional. (3) *#547's exit contract omitted `INCOMPLETE`.* The status vocabulary allowed it and Scenario 6 required a non-zero exit, but no code was assigned, so the two twins could legitimately disagree. `INCOMPLETE` is now fail-closed on exit `1`, never `2`, with the precedence between them stated.

- **`pk:doctor` Now Reads the `init.sh` Host-File Variants (#585)**: `check-doctor.{sh,ps1}` mapped `cline` to `.clinerules` and `cursor` to `.cursorrules` only, so a healthy directory-form cline install (`.clinerules/promptkit.md`, exactly what `init.sh ensure_target` writes) reported `host:.clinerules INCOMPLETE host file unreadable` and exited `1`, while a cursor `.cursor/rules/promptkit.mdc` install was missed as `SKIP(not installed)`. `host_relpath` now resolves the same variants `init.sh` does — `.clinerules` when it is a regular file else `.clinerules/promptkit.md`; `.cursorrules` when present else the mdc path — so a healthy install is blessed and the present variant is audited. - **Synthetic-Base Preflight Closes Remote-Tracking Workspace Tips and Aligns Branch-Namespace Boundaries (#579)**: two edges from the #576/#578 review. The `branch-namespace|` class consulted only `refs/heads/`, so a commit that is the tip of a fetched `refs/remotes/<remote>/gitbutler/workspace` with no local workspace branch reported `UNKNOWN` and proceeded (a false negative that fails safe); the tip pass now classifies `refs/heads` **and** `refs/remotes`. Carrier classification used a shell prefix glob (`gitbutler/workspace*`) while the tip lookup used `for-each-ref`'s prefix-to-slash matching, so `gitbutler/workspace-backup` was classified tool-owned but never matched as a tip; both passes now share one predicate that treats a name as tool-owned only at a path-component boundary (equal to the prefix, or the prefix followed by `/`). The regression harness grows to 24 cases per twin (S22 remote-tracking tip -> `REFUSE`, S23 `workspace-backup` boundary crossing -> `OK`, S24 `workspace/<name>` subpath -> `REFUSE`), and the signals-file grammar and `docs/ADOPTION-GUIDE.md` state the boundary rule.
- **Provenance Anchor Gate Now Fails Closed When the Anchor Is Unreachable (#568)**: both twin suites printed `⚠️ SKIP` and exited 0 when the `docs/BENCHMARKS.md` anchor did not resolve to a commit in the clone. Squash merges orphan the PR-branch commit the anchor named, so the anchor went unresolvable exactly when it was most likely stale — and the guard silently disabled itself while reporting success, the same failure mode re-armed three times (#556, #564, #567). Both twins now print `❌ FAIL`, name the unreachable anchor commit, instruct restating the anchor in `docs/BENCHMARKS.md` to a commit reachable on `main`, and exit non-zero. Verified by reproducing the red before the fix (both twins `⚠️ SKIP`, exit 0) and the green after (both twins `❌ FAIL` naming `0000000…0001` and the restate instruction, exit 1), with the real anchor still `✅ PASS` in both.
